# Migration Plan: Full Conversion of 4 Upstream Apps

## Summary
Convert Marketing Studio, Workflows, Agents, and Design Agent from upstream into full working Higgsfield applications.

## Current State Analysis

### Target Higgsfield Repo (Open-Higgsfield-AI)
- **Routing**: Custom Vite-based router in `src/lib/router.js` with hash-based navigation
- **Apps Registered**: Image, Video, Cinema, Storyboard, Edit, Character, Effects, Avatar, Audio, Workflows, Agents, Design Agent, Marketing Studio, Assistant, Studio

### Current Implementation Status

| App | File | Lines | Status |
|-----|------|-------|--------|
| Marketing Studio | MarketingStudioApp.js | 355 | Full implementation with video generation, local storage history |
| Workflows | VibeWorkflowPage.js | 92 | **SHELL** - iframe to external app only |
| Agents | AIAgentApp.js | 278 | Partial - simulated chat responses, no API integration |
| Design Agent | DesignAgentApp.js | 291 | Partial - config only, no image generation |

### Upstream Package Analysis
- `packages/studio/src/components/WorkflowStudio.jsx` - React component with tabs (templates, my-workflows, published)
- `packages/studio/src/components/WorkflowUI.jsx` - Uses `workflow-builder` external package (React Flow based)
- `packages/studio/src/components/AgentStudio.jsx` - Template agents, user agents, conversations with chat
- `packages/studio/src/components/DesignAgentStudio.jsx` - Uses `design-agent` external package (CreativeCanvas)

**Critical Issue**: Upstream uses external packages (`workflow-builder`, `design-agent`) that are not available as npm packages. This requires building standalone implementations.

## Key Finding: Workflows is a Shell App
The `VibeWorkflowPage.js` loads an iframe from `/apps/vibe-workflow/`. This must be converted to a native Higgsfield component.

## Critical Upstream API Endpoints

The upstream `muapi.js` provides these key functions that need Higgsfield equivalents:

**Workflow Functions:**
- getTemplateWorkflows, getUserWorkflows, getPublishedWorkflows
- createWorkflow, updateWorkflowName, deleteWorkflow
- getWorkflowInputs, executeWorkflow
- getAllNodeSchemas, getWorkflowData
- runSingleNode, getNodeStatus

**Agent Functions:**
- getTemplateAgents, getUserAgents, getPublishedAgents
- getUserConversations

## Implementation Strategy

### Phase 1: Workflows - Build Native Implementation
Since upstream uses external `workflow-builder` package (React Flow + custom), we need to build a simpler native version:

1. **Create WorkflowBuilderApp.js** with:
   - Node palette (Text, Image, Video, OpenAI, Combine)
   - Canvas area with drag-and-drop (using interactjs - already in deps)
   - Properties panel for node configuration
   - Execute button with run tracking

2. **Workflow Node Types:**
   - Text Prompt Node - input for prompts
   - Image Generation Node - connects to MuAPI
   - Video Generation Node - connects to MuAPI
   - OpenAI Node - LLM processing
   - Output Node - saves to Library

3. **Execution Flow:**
   - Sequential node execution
   - Status polling for async operations
   - Result aggregation

### Phase 2: Agents - Add Real API Integration
1. Add OpenAI API call function
2. Add Supabase persistence for agents/conversations
3. Add template listing page

### Phase 3: Design Agent - Add Image Generation
1. Add MuAPI integration for design prompts
2. Add brand kit templates
3. Add export/download

### Phase 4: Marketing Studio - Add Handoffs
1. Add Library save functionality
2. Add Render/Director handoff
3. Add campaign management

## Technical Constraints

**No new heavy dependencies** - use existing:
- interactjs (already in package.json) for drag-drop
- axios for API calls
- @supabase/supabase-js for persistence
- No React Flow - build simpler vanilla JS version

**Must work with existing router** - hash-based navigation in `src/lib/router.js`

**Must not break build** - all new code must be Vite-compatible

## Supabase Schema

```sql
-- Workflows
CREATE TABLE workflows (
  id UUID PRIMARY KEY,
  user_id UUID,
  name TEXT,
  nodes JSONB,
  edges JSONB,
  created_at TIMESTAMP,
  updated_at TIMESTAMP
);

-- Workflow runs
CREATE TABLE workflow_runs (
  id UUID PRIMARY KEY,
  workflow_id UUID REFERENCES workflows(id),
  status TEXT,
  outputs JSONB,
  created_at TIMESTAMP
);

-- Agents
CREATE TABLE agents (
  id UUID PRIMARY KEY,
  user_id UUID,
  name TEXT,
  role TEXT,
  instructions TEXT,
  tools JSONB,
  created_at TIMESTAMP
);

-- Agent conversations
CREATE TABLE agent_conversations (
  id UUID PRIMARY KEY,
  agent_id UUID REFERENCES agents(id),
  messages JSONB,
  created_at TIMESTAMP
);

-- Design projects
CREATE TABLE design_projects (
  id UUID PRIMARY KEY,
  user_id UUID,
  name TEXT,
  type TEXT,
  outputs JSONB,
  created_at TIMESTAMP
);
```

## Key Finding: Existing MuAPI Service Layer

The Higgsfield repo already has a complete `src/lib/muapi.js` (767 lines) with functions for:
- **Image/Video Generation**: generateImage, generateVideo, generateI2V, generateMarketingStudioAd
- **Workflow Operations**: getTemplateWorkflows, getUserWorkflows, createWorkflow, updateWorkflowName, deleteWorkflow, executeWorkflow, runSingleNode, getNodeStatus
- **Agent Operations**: getTemplateAgents, getUserAgents, getUserConversations

This means Workflows can use existing MuAPI calls directly - no new API integration needed.
