## Constraint: ZERO Changes to Existing UI

**No frontend files will be modified.** This plan is additive only — new backend code to bridge the director app to OpenAI's Responses API.

## OpenAI Responses API vs Chat Completions

The user has specified we must use the **OpenAI Responses API** (`POST /v1/responses`) instead of the Chat Completions API (`POST /v1/chat/completions`). Key differences:

| Feature | Chat Completions | Responses API |
|---|---|---|
| Endpoint | `/v1/chat/completions` | `/v1/responses` |
| Image input type | `image_url` | `input_image` |
| Text input type | `text` | `input_text` |
| Message role | `user` | `user` (same) |
| Content array | `content: [{type: "text", text: "..."}, {type: "image_url", image_url: "..."}]` | `content: [{type: "input_text", text: "..."}, {type: "input_image", image_url: "..."}]` |
| Model param | `model` | `model` (same) |
| Input format | `messages: [...]` | `input: [...]` |
| Output access | `choices[0].message.content` | `output_text` (helper) or `output` array |
| Conversation state | Manual (send full history) | `previous_response_id` (server-managed) |
| Built-in tools | None | web_search, file_search, computer_use, code_interpreter, image_generation |
| Vision support | ✅ | ✅ |
| Stateful | ❌ | ✅ (stored by default) |
| Agentic loop | ❌ | ✅ (multi-turn tool use in one request) |

### Responses API Request Format for Vision

```json
{
  "model": "gpt-4.1-mini",
  "input": [
    {
      "role": "user",
      "content": [
        { "type": "input_text", "text": "Describe what's in these video frames" },
```

```json
}
```

## Can OpenAI Cover the 5 Partial-Coverage Agents?

**YES — OpenAI can cover all 5 partial-coverage agents using the Responses API.** Here's exactly how:

### 1. Video Summarization → ✅ Responses API with GPT-4.1 Vision

**How it works:** Extract frames from video, send as `input_image` items in the `input` array. The model analyzes all frames and returns a comprehensive summary.

**API:** `POST /v1/responses` with `gpt-4.1-mini` or `gpt-4o`

**Request format:**
```json
{
  "model": "gpt-4.1-mini",
  "input": [
    {
      "role": "user",
      "content": [
        { "type": "input_text", "text": "Summarize this video based on these frames. Include key topics, scenes, and important moments." },
        { "type": "input_image", "image_url": "data:image/jpeg;base64,...", "detail": "high" },
        { "type": "input_image", "image_url": "data:image/jpeg;base64,...", "detail": "high" }
      ]
    }
  ]
}
```

**Implementation approach:**
```
1. Download video from URL using ffmpeg
2. Extract frames at 1 fps using ffmpeg: ffmpeg -i video.mp4 -vf "fps=1" frame_%04d.jpg
3. Encode each frame as base64
4. POST to /v1/responses with all frames as input_image items
5. Return output_text as the summary
```

**Cost:** ~$0.15/1M input tokens + $1.00/1M output tokens (gpt-4.1-mini). ~$2.50/1M input + $10.00/1M output (gpt-4o).

### 2. Video Search → ✅ Responses API with GPT-4.1 Vision

**How it works:** Same frame-sampling approach, but the prompt asks the model to find specific moments matching a user query and return timestamps.

**API:** `POST /v1/responses` with `gpt-4.1-mini`

**Request format:**
```json
{
  "model": "gpt-4.1-mini",
  "input": [
    {
      "role": "user",
      "content": [
        { "type": "input_text", "text": "Search this video for moments where the speaker discusses 'product pricing'. Return the timestamps (in frame numbers) and a brief description of each matching moment." },
        { "type": "input_image", "image_url": "data:image/jpeg;base64,...", "detail": "low" }
      ]
    }
  ]
}
```

**Implementation approach:**
```
1. Download video, extract frames at 1 fps with timestamps
2. Encode frames as base64
3. POST to /v1/responses with search query + frames
4. Parse output_text for matching timestamps
5. Return structured search results
```

### 3. Subtitle Generation → ✅ Responses API with Whisper

**How it works:** Extract audio from video, send to Whisper via the Responses API (or the dedicated Audio API). Whisper transcribes speech with word-level timestamps and can output SRT/VTT format directly.

**API:** `POST /v1/audio/transcriptions` with `whisper-1` or `gpt-4o-transcribe`

**Request format (multipart):**
```
POST /v1/audio/transcriptions
Content-Type: multipart/form-data

file: <audio file>
model: whisper-1
response_format: srt
language: en
```

**For word-level timestamps:**
```
response_format: verbose_json
timestamp_granularities: ["word", "segment"]
```

**Implementation approach:**
```
1. Extract audio from video: ffmpeg -i video.mp4 -vn -acodec mp3 audio.mp3
2. POST audio to /v1/audio/transcriptions
   - model: "whisper-1" or "gpt-4o-transcribe"
   - response_format: "srt" (for direct subtitle output)
3. Return SRT text as subtitles
```

**Whisper model options:**
| Model | Quality | Speed | Cost |
|---|---|---|---|
| `whisper-1` | High | Standard | $0.006/min |
| `gpt-4o-transcribe` | Highest | Fast | Higher |
| `gpt-4o-mini-transcribe` | High | Fastest | Lower |
| `gpt-4o-transcribe-diarize` | Highest + speaker labels | Fast | Higher |

### 4. Highlight Extraction → ✅ Responses API with GPT-4.1 Vision

**API:** `POST /v1/responses` with `gpt-4.1-mini`

**Request format:**
```json
{
  "model": "gpt-4.1-mini",

    {

        { "type": "input_image", "image_url": "data:image/jpeg;base64,...", "detail": "high" }

```

**Implementation approach:**

### 5. Scene Detection → ✅ Responses API with GPT-4.1 Vision

**How it works:** Extract frames at high frequency, send to GPT-4.1 with a prompt asking it to identify scene boundaries (significant changes in location, subject, or visual composition).

**API:** `POST /v1/responses` with `gpt-4.1-mini`

**Request format:**
```json
{
  "model": "gpt-4.1-mini",
  "input": [
    {
      "role": "user",
      "content": [
        { "type": "input_text", "text": "Analyze these video frames and identify all scene boundaries. A scene boundary is when there is a significant change in location, subject, camera angle, or visual composition. Return a list of frame numbers where scene changes occur, with a brief description of each new scene." },
        { "type": "input_image", "image_url": "data:image/jpeg;base64,...", "detail": "low" }
      ]
    }
  ]
}
```

**Implementation approach:**
```
1. Download video, extract frames at 4 fps with frame numbers
2. Encode frames as base64
3. POST to /v1/responses with scene detection prompt
4. Parse output_text for scene boundary timestamps
5. Return scene segments with start/end times
```

### 6. Video Stabilization → ⚠️ FFmpeg (not OpenAI)

**OpenAI cannot do video stabilization.** This is a signal processing task. Use FFmpeg's free `vid.stab` filter.

**Implementation approach:**
```
1. Download video
2. Run: ffmpeg -i input.mp4 -vf vidstabdetect=shakiness=5:accuracy=15 -f null -
3. Run: ffmpeg -i input.mp4 -vf vidstabtransform=smoothing=30:input="transforms.trf" -c:a copy output.mp4
4. Upload stabilized video to storage
5. Return stabilized video URL
```

- **`callOpenAIVision(frames, prompt, model)`** → POST to `/v1/responses`:
  ```json

      "role": "user",
      "content": [
  ```

- **`callWhisper(audioBuffer, format)`** → POST to `/v1/audio/transcriptions`:

### Key Implementation Notes

1. **Frame extraction:** Use ffmpeg in the edge function (or a separate processing service) to extract frames. Deno edge functions may not have ffmpeg — consider using a Supabase Edge Function with a Docker container or an external processing service.

2. **Image detail levels:** The Responses API supports `detail: "low"` (512x512, cheap), `detail: "high"` (full resolution, expensive), or `detail: "auto"`. Use `"low"` for scene detection (many frames), `"high"` for summarization and highlights (fewer frames).

3. **Token limits:** gpt-4.1-mini has a 1M token context window. At ~1000 tokens per high-res image, you can send ~1000 frames max. For a typical video, 100-200 frames at 1-2 fps is sufficient.

4. **Stateful conversations:** The Responses API supports `previous_response_id` for multi-turn conversations. This is useful for iterative video analysis (e.g., first pass detects scenes, second pass summarizes each scene).

5. **Async processing:** Video analysis can take 30-60 seconds. Use the `store: true` (default) and return a `response_id` that the frontend can poll for results.
