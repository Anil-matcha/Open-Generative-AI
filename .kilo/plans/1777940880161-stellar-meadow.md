# Plan: Fix MuAPI "UNAUTHORIZED_NO_AUTH_HEADER" 401 Error

## Problem Statement

After adding a MuAPI key in Settings, API requests fail with:
```
Error: API Request Failed: 401 - {"code":"UNAUTHORIZED_NO_AUTH_HEADER","message":"Missing authorization header"}
```

This indicates MuAPI is **not receiving** the `x-api-key` header, even though the client is sending `x-user-api-key` to the Edge Function.

## Root Cause Analysis

The request flow is:
```
Browser (x-user-api-key) → Edge Function → MuAPI (x-api-key)
```

The error means the header is missing between Edge Function → MuAPI. Most likely causes:

1. **CORS blocking header from being sent** – `x-user-api-key` must be in `Access-Control-Allow-Headers`
2. **Edge Function not forwarding header correctly** – variable scope or header name mismatch
3. **Client not sending header** – fetch call missing the header due to code path

## Solution Steps

### 1. Fix Edge Function CORS (Primary Fix)

**File:** `supabase/functions/muapi-proxy/index.ts`

Update `getCorsHeaders()` to include `x-user-api-key` in the allowed headers list using **lowercase** to exactly match what the browser sends:

```ts
return {
  "Access-Control-Allow-Origin": origin,
  "Access-Control-Allow-Methods": "GET, POST, PUT, DELETE, OPTIONS",
  "Access-Control-Allow-Headers": "Content-Type, Authorization, X-Client-Info, Apikey, x-user-api-key",
  "Access-Control-Allow-Credentials": "true"
};
```

Why lowercase? The browser sends `x-user-api-key` (lowercase) in `Access-Control-Request-Headers`. The allow-list must contain a case-insensitive match; using lowercase avoids any potential case-sensitivity issues.

### 2. Add Edge Function Request Logging (Debug)

Inside the main request handler, after reading the header:

```ts
const muapiKey = req.headers.get('x-user-api-key');
const keyPreview = muapiKey ? `${muapiKey.slice(0, 4)}***` : 'MISSING';
console.log(`[muapi-proxy] Received user key: ${keyPreview}, forwarding to MuAPI`);
```

This confirms the Edge Function receives the header and will forward it.

### 3. Verify Header Forwarding

Ensure the fetch to MuAPI uses the exact key:

```ts
const fetchOptions: RequestInit = {
  method,
  headers: {
    'Content-Type': 'application/json',
    'x-api-key': muapiKey // ← forwarded as this
  }
};
```

This is already present; no change needed unless logging shows otherwise.

### 4. Redeploy Edge Function

```bash
supabase functions deploy muapi-proxy
```

Verify deployment succeeded in Supabase Dashboard.

### 5. Client-Side Verification

**Currently implemented** in `src/lib/muapi.js`:

- `makeRequest()` and all generation methods call `await this.getOptionalUserKey()` and send in `x-user-api-key` header.
- `uploadFile()` uses the proxy with the required key.
- `processLipSync()` uses the proxy.

No client changes needed, but we can optionally add a sanity check:

In `src/lib/muapi.js`, inside `makeRequest()` before fetch, add:

```js
const userKey = await this.getOptionalUserKey();
if (!userKey) {
  throw new Error('API key not configured. Please add your MuAPI key in Settings.');
}
```

(Note: `requireKey()` exists but not used in all methods; `getOptionalUserKey` is fine because Edge Function will also reject.)

### 6. User Action Required

After deployment:

1. Clear browser localStorage for the site (or use incognito) to avoid old encrypted data.
2. Open Settings and re-enter your MuAPI key (click Save).
3. Try a simple generation (e.g., generate image).
4. Open browser DevTools → Network tab:
   - Verify the request to `muapi-proxy` includes header `x-user-api-key: sk-...`
   - Verify the response is 200.

If still failing, check Edge Function logs in Supabase Dashboard → Functions → Logs to see the `keyPreview` log.

### 7. Fallback: Direct MuAPI Calls (if proxy still fails)

If the issue persists, we can bypass the proxy for user-provided keys:

- Modify `src/lib/muapi.js` to call `https://api.muapi.ai` directly when `userKey` exists, while still using proxy for server-side features.
- This removes Edge Function as a point of failure.

**Note:** Direct calls require MuAPI to support CORS. Their examples show browser-based fetch, so CORS is allowed.

### 8. Final Validation

After fix:
- No more "API key required" or 401 toasts on startup.
- Generation succeeds with user's own MuAPI quota.
- Edge Function logs show successful forwarding.
