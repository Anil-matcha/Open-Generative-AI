# Netlify Monorepo Deployment Fix Plan
## Problem Statement
Netlify is recognizing individual apps (ai-headshot-generator, agents, marketing-studio, etc.) as separate repositories requiring URLs during deployment, despite being part of a monorepo.

## Root Cause Analysis
- Apps directory contains individual package.json files
- Netlify's monorepo detection is incorrectly treating each app as a separate deployable unit
- Build configuration in netlify.toml uses `pnpm run build:all` but Netlify still scans individual apps

## Solution Approach
Implement proper monorepo exclusion patterns to prevent Netlify from treating individual apps as separate deployments.

## Implementation Strategy
1. Create .netlifyignore file to exclude individual apps
2. Update .gitignore to ensure apps aren't treated as separate repos
3. Verify build configuration prevents individual app detection
4. Test deployment to confirm fix

## Risk Assessment
- Low risk: This only affects deployment detection, not functionality
- Monorepo structure remains intact
- Apps still build correctly within monorepo context

## Success Criteria
- Netlify deployment no longer prompts for URLs for individual apps
- Monorepo builds successfully as single deployment
- All apps remain accessible through main application routing
